# 单音口琴旋律生成

导入 MIDI / MusicXML 后默认使用原版：保留起音，和弦取最高音。用户可以选择 Symbolic CNN 或原有的自研精简模式。MP3 的 Basic Pitch 转录和音频分析阶段保持独立。

## 开源算法选项

### Symbolic CNN

使用 LIMUNIMI/Symbolic-Melody-Identification 的已训练 `nn_kernels_pop.pkl` 权重，来源修订记录在 `public/melody/symbolic-pop.json`。通过 `scripts/convert-symbolic-weights.py` 转成浏览器可读的浮点权重，运行时不加载 pickle。卷积核维度与翻转、两层卷积、共享权重的 InverseLayer 雅可比以及 sigmoid 均移植到 TensorFlow.js；优先使用 Worker WebGL，不能使用时退回 CPU。

模型使用每拍 8 格、128 音高、64 格窗口和 50% 重叠。音符概率取对应网格的中位数，再映射回原始音符，模型网格不改写原来的起音和音长。

这不是原 Python 程序的完整复刻：页面以用户可调阈值代替原工程的聚类阈值和图后处理，并在完全同时起音时优先保留概率较高的音符，最后经过现有单音处理。默认阈值为 0.35，降低阈值可以保留更多细节，也可能带回伴奏。模型的适用曲风、跨运行时数值一致性和实际听感仍需验证，仍应按实际曲目试听调整。

来源：https://github.com/LIMUNIMI/Symbolic-Melody-Identification ，MIT 许可证位于 `public/licenses/symbolic-melody-LICENSE.txt`。首次加载权重，后续修改阈值无需重新推理。

模型权重和元数据随项目保存，从与页面相同的站点按需加载。页面以互斥勾选框展示三种算法，每次选择一项。

## 自研精简模式的选音方式

- 先按真实静音分句，避免较弱的独立乐句被其他乐句挤掉。长音期间的起音仍属于同一段。
- 对已经单音的段落保留原来的音高、起音、重复音和休止。轻微的 MIDI 连奏重叠只截短前一个音，并同步拍长。
- 对复音段落，把 45 毫秒以内的起音归为一组，合并候选中的同音加倍，每组最多保留 12 个不同音高候选。
- 用最多 64 条候选路径的束搜索逐组比较“换音”和“保持当前声部”。路径综合音长、力度、音区、整拍位置、音程连续性、重叠和密度打分；正在延续的音符按实际覆盖时长获得分数，使密集伴奏不能仅凭音符数量胜出。
- 评分时间尺度随传入曲速调整；45 毫秒和弦窗口仍是固定的演奏约束。输出不移动起音、不合并重复按音，最后统一去除重叠。

这是本地启发式算法，没有新增模型下载或网络请求。它不会判断乐器身份或演奏意图；复杂合奏仍优先选择主旋律轨道。变速曲当前使用导入曲速作为筛选参考，原有音符时间和节奏数据继续保留。音域移调与键位优化由后续的“自动适配”处理。

回归样例覆盖单音快句、同音重复、连奏拍长、静音分句、中声部与高音装饰、长音穿插密集伴奏、同音加倍、曲速缩放和输入顺序。实际曲目听感需要试听确认。
