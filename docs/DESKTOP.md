# 桌面版自动演奏 / 可视化演奏器

`desktop/` 目录是一个 WPF（.NET 9）程序：打开本站导出的 MIDI 或公开曲库里的谱面，按网页端完全相同的指法向《三角洲行动》发送口琴按键。它不是通用 MIDI 播放器，作谱、编辑、发布仍在网页端完成。

## 界面布局

- 顶部「演奏 / 设置」切换工作页；演奏页左侧选本地或公开曲库，右侧选择演奏方式、查看谱面和本次练习成绩。
- 底部播放条始终可用：上一首、开始、暂停、停止、下一首集中排列；状态提示和进度位于同一区域。长状态与环境信息悬停可看完整内容。
- 设置按「快捷键」「播放与时序」「悬浮窗」「曲库」分类，保存与恢复默认固定在页底。底部「外观…」直接打开悬浮窗设置，透明度与音符流速调整立即保存。
- 悬浮窗只显示即时演奏信息和精简成绩；完整误差统计在主窗口展开查看。

## 下落音符悬浮窗

载入谱面后，点击主窗口底部的「隐藏 / 显示悬浮窗」。悬浮窗独立于演奏模式，可与自动演奏同时开启；底部用「手动演奏 / 自动演奏」两选开关切换模式，首次启动默认手动，之后记住选择。手动模式的开始按钮只驱动音符时间轴，不发送按键，并确保悬浮窗已打开。手动模式至少预留 3 秒倒计时。

| 默认热键 | 功能 |
| --- | --- |
| F5 | 开始 / 结束，结束后再次开始从头播放 |
| F6 | 暂停 / 继续，保留当前进度，也可暂停倒计时 |
| F7 | 隐藏 / 显示悬浮窗，不改变播放状态 |
| F8 | 本地曲库上一首 |
| F9 | 本地曲库下一首 |
| F10 | 进入 / 退出悬浮窗键盘调整，退出时保存 |

在左侧「设置」页分别选择六项热键（F1–F24），点击「保存」立即生效并记住；重复热键不能保存。「恢复默认」需保存后生效。设置页在前台编辑时暂不响应全局热键，下方播放按钮仍可使用，切回游戏后热键正常响应。旧版配置中的默认悬浮窗 F6 自动迁移到 F7，非默认设置保留；与新增热键冲突时自动分配空闲功能键。

### 游戏锁定鼠标时调整悬浮窗

按 F10（或主窗口「键盘调整悬浮窗」）进入调整模式，悬浮窗自动显示，高亮边框与提示说明当前正在调整。无需切出游戏或解除鼠标锁定，播放状态保持不变。

| 默认操作 | 效果 |
| --- | --- |
| ← ↑ → ↓ | 对应方向移动，每次 10 个物理像素；长按连续移动 |
| Shift + 方向键 | 每次 1 像素微调 |
| Ctrl + ← / → | 减小 / 增大宽度 |
| Ctrl + ↑ / ↓ | 减小 / 增大高度 |
| Ctrl + Shift + 方向键 | 每次 1 像素调整宽高 |
| F10 | 退出调整并保存 |
| F7 | 退出调整、保存并隐藏 |

调整键、微调和缩放修饰键仅在调整模式中拦截；F10 开关键也会拦截，防止触发其他程序的菜单。退出时仍配对拦截此前按下的键的松开事件；进入调整前已经按住的键会透传到松开，松开后重新按下即可调整。方向键可在设置页改为箭头或 A–Z，Shift/Ctrl 两种修饰键可交换。设置页在前台编辑时调整键也暂停拦截。窗口最小尺寸和虚拟桌面外边界有限制，保存后下次启动恢复位置。

上一首 / 下一首读取当前本地曲库文件夹，按列表的文件名顺序首尾循环，以已载入的歌曲为基准。当前歌曲不在本地列表时，下一首载入第一首、上一首载入最后一首；空曲库禁用切歌。播放或倒计时中切歌会先松开旧曲按键，再按设置重新倒计时开始新曲；暂停或空闲时切歌只载入，按 F5 开始。连续切歌请求在切换期间忽略，F5 可取消正在等待的切换。目录刷新会保留仍然存在的选中歌曲。

暂停会冻结谱面进度和下落音符。自动模式暂停时松开全部音键与鼠标修饰键，继续时先恢复修饰键并等待所选档位的提前量，再恢复尚未结束的长音；暂停期间可切换窗口。启用「前台窗口切换时自动停止」时，继续前需切回原游戏窗口，否则结束播放。暂停期间仍可使用 F5 结束、F7 切换悬浮窗。

八条轨道从左到右对应 Z、X、C、V、B、N、M、逗号。音符下缘到白线时按下，长条尾端到线时松开。绿色为原调，蓝色 ↓ 为降调，橙色 ↑ 为升调；半音用粉色边框和 # 标记，可以与升降调同时显示。

停止时拖动标题移动悬浮窗、拖动右下角调整大小；「键位提示」开关可以同时隐藏音符上的文字提示和底部键位（保留颜色），以便与游戏自带键位对齐。位置、尺寸、键位显示和演奏模式自动保存到 `%LocalAppData%\DeltaForceHarmonica\overlay.json`。播放期间悬浮窗置顶、锁定并让鼠标穿透；按停止热键后恢复编辑。主窗口最小化不隐藏悬浮窗，退出程序会关闭悬浮窗。

游戏需使用无边框或窗口模式；普通桌面置顶窗不保证覆盖独占全屏。自动模式按实际编排后的按下 / 松开时间显示（包括时序档位产生的延迟），手动模式按原谱时间显示。

## 逐音练习、节奏计分与误差

演奏页直接并列显示「普通模式」「练习模式」「计分模式」「自动演奏」。普通模式自由下落、不判定；练习模式逐音等待；计分模式按节奏评分。空闲时可切换，选择会保存。练习监听实际键盘音键 Z/X/C/V/B/N/M/逗号，以及鼠标左键（降八度）、右键（升八度）、中键（半音）。必须匹配当前谱面显示的键位和修饰键；左右键同时按下视为不匹配。按键不会被练习功能吞掉，仍传给游戏；长按产生的重复按下、自动演奏注入事件不参与计分。

- **自由下落**：沿用原有行为，不计分。
- **逐音练习**：一次显示当前一个音符；到判定线后等待，按对才放行下一个音符，错按不跳过。统计正确数、错按、正确率、连击，以及最近/平均反应时间。反应时间从当前音符到线开始计算，扣除暂停时长，与节奏误差分开。下一音保留原谱相邻起音间隔。
- **节奏计分**：音符持续下落，按对且起音误差在 ±50 ms 内记 Perfect（1000 分），±150 ms 内记 Good（500 分），超过 +150 ms 未命中记 Miss（0 分）。错按和 Miss 中断连击；密集音符按最近且尚未命中的匹配音符判定。命中率 = 命中数 /（命中数 + 漏音数 + 错按数）。

误差单位为毫秒，负数表示提前、正数表示延后；窗口内按对的音符才是有效样本。主窗口「本次练习」显示成绩，展开「误差与反应时间」可查看最近误差、平均有符号偏差、平均绝对误差、最大绝对误差、标准差和样本数。悬浮窗显示精简成绩、连击与最近误差，完整统计在主窗口查看。漏音和错按不会被伪造为固定误差样本。输入时间在键盘钩子回调时记录，避免将 UI 排队时间当作用户误差。

开始前至少倒计时 3 秒，倒计时按键不计分；切回游戏后绑定该前台窗口，切出则自动暂停（计时及计分冻结），切回后按 F6 继续。F7 隐藏悬浮窗不影响判定；进入 F10 调整模式会暂停练习，退出后按 F6 继续。停止保留已完成的成绩，未演奏的后续音符不算漏音；再次开始、换谱或切换模式会清空成绩。

这版只判定键位和**起音时机**，不评价长音松键时机，也不能确认游戏实际发声。误差为本地谱面时间与捕获到的按键时间之差，未补偿设备、系统和游戏的输入/音频延迟。

## 目录结构

```text
desktop/
  DeltaForceHarmonica.sln
  DFH.Core/          与网页共享的谱面管线（C# 移植）：DFHS1 解码、单音收敛、指法优化、按键序列、小节切分、曲库客户端、MIDI 读取
  DFH.Core.Tests/    一致性测试；Fixtures/ 里的黄金样本由网页端 `npm run fixtures:desktop` 生成
  DFH.Desktop/       WPF 界面、SendInput 发键、播放线程、全局热键、设置
  smoke.ps1          开发用 UI 冒烟脚本（启动、点按钮、截图）
```

## 数据流

```text
网页导出 .mid ──┐
                ├─► DFHS1 快照 ─► enforceMonophonic ─► optimizeHarmonica(transpose) ─► buildKeySequence ─► 播放线程 ─► SendInput
曲库 CDN JSONP ─┘
```

**两端只有一种内部格式。** 网页端导出 MIDI 时把 DFHS1 快照（收敛后的音符 + 移调 + tempo 表）以 base64url 写进一条 MIDI 文本 meta 事件（前缀 `DFHS1 `，见 `src/export/midi.ts`）。桌面端只认这条事件；老版本导出的文件只有 `DFH SCORE` 轨名，按纯音高路径兼容打开并标注「旧版导出」；其他 MIDI 一律拒绝。

公开曲库不需要任何后端改动：桌面端直接读 CloudBase CDN 上的 `index.js`、`catalog/{0..f}.js`、`score/{id}.js`，去掉 `__dfh("key", …)` 包裹后解析 JSON，`p` 字段里的 DFHS1 走同一条管线。Toy 私人云存档依赖 B 站页面内的 SDK，桌面端拿不到。

## 一致性保障

`src/harmonica/optimizer.ts` 等五个 TypeScript 文件是权威实现，C# 是逐行移植。`scripts/desktop-fixtures.ts` 用网页管线跑五组样本（音阶、全音域修饰键、和弦/重叠、变速 + 换拍号、400 音随机），把解码结果、单音收敛、指法、最佳移调、按键序列全部写成 JSON；`DFH.Core.Tests` 用 C# 重跑并要求逐字节一致（cost 允许浮点误差）。

改了网页端的映射、优化器权重、按键时序默认值后，必须重新生成样本并同步 C#：

```bash
npm run fixtures:desktop
cd desktop && dotnet test
```

移植时踩过的坑：JS `Math.round` 是向 +∞ 取整，C# 要用 `Math.Floor(x + 0.5)`；JS 的 `sort` 稳定，C# 用 `OrderBy/ThenBy` 而不是 `List.Sort`；候选按法枚举顺序和严格小于的平局规则决定指法结果，不能改。

## 按键注入

`InputSender` 用 `SendInput`，键盘事件只填扫描码（`wVk=0` + `KEYEVENTF_SCANCODE`），鼠标修饰键用 `MOUSEEVENTF_*`。前提条件：

1. 程序以管理员运行（`app.manifest` 声明 `requireAdministrator`）。游戏是高完整性进程，未提权发的输入会被 UIPI 拦掉，这和网页端提示「外设软件要提权」是同一个原因。
2. 游戏用窗口化或无边框，全屏独占收不到模拟输入。
3. 前台输入法切英文，中文 IME 会截走按键。

播放线程按绝对时间派发，提前 2 ms 从睡眠切到自旋；`timeBeginPeriod(1)` 提高定时精度。任何停止路径（热键、前台窗口切换、异常）都先松开全部按键。全局热键用 `WH_KEYBOARD_LL` 钩子，普通播放热键透传，调整模式拦截相应调整键，忽略自己注入的事件。

提权窗口收不到资源管理器的 OLE 拖放，`DropFiles` 用 `ChangeWindowMessageFilterEx` 放行 `WM_DROPFILES` 实现拖文件。

「打开网页版」按钮通过 `explorer.exe <url>` 打开链接：提权进程直接 ShellExecute 可能拉起一个带管理员权限的浏览器实例，交给已在运行的非提权资源管理器转发可以避免。地址常量在 `Services/Links.cs`。

## 构建与发布

```bash
cd desktop
dotnet test                                   # 核心一致性测试
dotnet build DFH.Desktop                      # 需要 UAC 的正式版
dotnet build DFH.Desktop -p:DfhNoAdmin=true   # 开发用，不提权，按键到不了提权的游戏
dotnet publish DFH.Desktop -c Release -r win-x64 --self-contained -p:PublishSingleFile=true -p:IncludeNativeLibrariesForSelfExtract=true -o publish
```

发布产物是单个 `DeltaForceHarmonica.exe`。未签名的提权程序会触发 SmartScreen 提示，正式分发建议代码签名。

设置保存在 `%LocalAppData%\DeltaForceHarmonica\settings.json`：热键、倒计时、按键时序档位、曲库地址。

按键时序分三档，与网页导出面板同名同值（`src/export/timing.ts` 与 `DFH.Core/Export/KeySequence.cs` 里的 `TimingTiers` 必须同步改）：

| 档位 | 修饰键提前 | 松键到下一次按下 | 最短按住 | 适用 |
| --- | --- | --- | --- | --- |
| 稳健 | 70 ms | 70 ms | 80 ms | 30 fps、卡顿机器 |
| 标准（默认） | 40 ms | 40 ms | 45 ms | 60 fps |
| 极限 | 20 ms | 18 ms | 22 ms | 高帧率、快歌 |

这三项是硬下限而不是目标值：游戏按帧采样，修饰键与音键落在同一帧会出错音，松键与下一次按下落在同一帧会漏音。密集乐段里编排器会推迟音符来保住间隔，而不是把它们挤进同一帧。「自定义」档解锁三个毫秒输入框。旧版 settings.json 没有档位字段，读入后按标准档处理。

## 风险说明

在线对局使用自动输入违反游戏协议，有封号风险。程序首页有明确提示，仅建议在练习、自定义房间等不影响他人的场景使用。

### 结束结果面板

练习或计分自然结束、手动停止后，在主窗口显示独立结果面板，区分「已完成」和「提前结束」。计分模式显示总分、命中率、最高连击、Perfect/Good/Miss/错按与完整起音误差；练习模式显示正确音符、正确率、错按与反应时间。关闭后可从「上次结果」重新打开；结果在当前进程中保留为快照，开始新曲或切换模式不会改写上次结果，下一次结束时更新。普通模式和自动演奏不生成结果。
