# 口琴输入映射（待实测）

## 当前假设

根据游戏 UI：

| 基础键 | 简谱 |
| --- | --- |
| Z | 1 |
| X | 2 |
| C | 3 |
| V | 4 |
| B | 5 |
| N | 6 |
| M | 7 |
| , | 高音 1 |

修饰键暂定：

- 降调：音符下方出现点，按 `-12 semitones` 处理。
- 半音：音符左上角出现 `#`，按 `+1 semitone` 处理。
- 升调：音符上方出现点，按 `+12 semitones` 处理。

## 为什么映射保留候选按法

十二平均律下会出现同音异键，例如在 `1=C` 时：

- `4` = F
- `#3` = F

因此转换器不能简单做 `pitch -> key` 的单值映射。`candidatesForPitch()` 会返回所有候选按法，再由动态规划根据半音状态切换、八度状态切换和键位移动选择整段旋律成本较低的路径。

## 取得道具后的验证清单

1. 录制基础 `Z X C V B N M ,` 的实际音高。
2. 分别测试升调、降调后是否严格相差 12 semitones。
3. 测试半音是否对所有基础音固定 `+1 semitone`。
4. 测试 `#3` 是否与 `4` 同音、`#7` 是否与高音 `1` 同音。
5. 测试升/降调是否可以与半音同时保持。
6. 测试修饰状态是按住生效、切换生效，还是存在其它输入状态机。
7. 测试逗号键在升/降八度状态下的边界行为。

若实测结论不同，优先只修改 `src/harmonica/mapping.ts`。
